# Evaluation Protocol - V3.1 section 7

V4 evaluation is **strictly V3.1 section 7**. No bootstrap CI, no ablations, no shortcut audit - locked decision F per the V4 plan. This document explains what we measure, how we measure it, and the two risks we accept by skipping deeper diagnostics.

---

## 1. What we report

For each trained Stage 2 checkpoint, on each evaluation split:

| Metric | Type | Notes |
|--------|------|-------|
| Precision per class | float[5] | Spec section 7 |
| Recall per class | float[5] | Spec section 7 |
| F1-macro | float | Primary headline number |
| Accuracy | float | Secondary headline |
| Confusion matrix (5x5) | int matrix | PNG + JSON |
| Classification report | str | sklearn `classification_report` text |

Per-source breakdown (filter by `df["source"]`) is also produced as `per_source_metrics.json` for visual inspection. It is NOT a primary deliverable; it's a diagnostic.

---

## 2. Splits

| Split | Description |
|-------|-------------|
| **in_distribution_test** | The 15% held-out test partition of `forensic_5class_v4.csv` |
| **mmfakebench_transfer** | All rows in the dataset whose `source` starts with `MMFakeBench_` (regardless of train/val/test partition); a separate convenience pass also re-runs over `data/raw/MMFakeBench/MMFakeBench_test/` directly |

The in-distribution test split was stratified by `(label, source)` at manifest-build time - see `src/v4/data/builders/merge.py::_stratified_split`. This means each source appears in train/val/test proportionally, eliminating source-fingerprint shortcuts (V3 lesson).

---

## 3. Running the evaluation

```bash
make eval
```

Which expands to:
```bash
python -m v4.cli eval --config configs/v4_pipeline_qwen.yaml --split test
python -m v4.cli eval --config configs/v4_pipeline_qwen.yaml --split mmfakebench-transfer
```

The CLI loads the best Stage 2 checkpoint from `outputs/v4/stage2_fusion/seed_<S>/best.pt`, deactivates the aux head, runs softmax on `main_logits`, and writes artifacts to:

```
outputs/v4/eval/
  in_distribution_test/
    metrics.json
    confusion_matrix.png
    classification_report.txt
    per_source_metrics.json
  mmfakebench_transfer/
    metrics.json
    confusion_matrix.png
    classification_report.txt
    per_source_metrics.json
```

---

## 4. Reporting across seeds

Stage 2 trains 3 seeds (42, 1337, 2024). The Day-5 evaluation runs each seed independently and the reporting layer (`evaluation/reporting.py`) computes mean and std for the F1-macro and accuracy.

The "best-seed checkpoint" used for downstream deployment is the seed with the highest val F1-macro (NOT test F1 - test is held out for the doctor).

---

## 5. Aux-head deactivation at inference

The V3.1 spec is unambiguous: the aux head (binary "image is AI/tampered") is a regularizer only. At inference time, `BaseEvaluator.predict` calls `fusion(features)` but uses only `out["main_logits"]`. The aux head is wired but its output is discarded.

This is asserted by `tests/spec_compliance/test_v3_1_section_5_3_pairwise_sum.py` indirectly: the test confirms the fusion shape is correct so the evaluator's slicing is valid.

---

## 6. Confusion-matrix conventions

- Rows = true label (top-down: Real, OOC, Manipulated, AI-Text, Fully-Fabricated)
- Cols = predicted label (left-right: same order)
- Diagonal cells = correct predictions
- Colormap: blue (low) -> dark (high), `viridis` via matplotlib
- The PNG is generated by `evaluation/reporting.py::write_confusion_matrix_png`

Label names come from `core/class_map.py::LABELS` so any renaming there propagates automatically.

---

## 7. Risks accepted

### R1 - No shortcut audit

V3 spent weeks chasing an undetected Class 4 caption-fingerprint leak: the BLIP-2 captions in MMFakeBench's AI-image-AI-text rows had distinctive prefixes that the text encoder learned as a shortcut. V4 mitigates this with two structural defenses:
1. Stratified split by `(label, source)` - no `source` is fully in train OR fully in test.
2. Class 4 augmentation from DGM4 multimodal-paired-fake - adds non-MMFB Class 4 samples.

But V4 does **not** ship a positive shortcut detector (e.g. probing classifier on text only). If a new shortcut appears post-deployment, we won't catch it until we see anomalous per-source F1.

**Watch-for:** any single per-source F1 > 0.95 should trigger manual investigation.

### R2 - Per-source bias

The per-source breakdown is for visual inspection only. There's no automated threshold or alert. If MMFakeBench transfer F1 differs from in-distribution F1 by more than ~0.20, dig into per-source numbers before trusting the headline.

---

## 8. What "PASS" means

Per the locked decision in V4 plan section 1, the V4 PASS gate is:
1. All four V3.1 section 7 metrics produced on test + transfer splits.
2. No leakage-audit failures.
3. Doctor reviews the reports.

There is no quantitative numeric threshold for "ship" vs "no-ship" - the doctor signs off based on the artifacts.
